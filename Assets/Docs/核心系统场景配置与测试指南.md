# 核心系统场景配置与测试指南

本文档面向关卡策划、TA、测试和后续接手项目的开发者，说明当前 Unity 项目中各项核心功能的工作方式、场景配置方法和测试流程。

推荐统一在 `BombTest_REElevel 04` 中验证机关，再制作或覆盖正式 Prefab。

> 重要：当前炸弹交互主要由组件接口决定，而不是只看 Tag。`Default`、`air` 等 Tag 可以用于分类，但仅修改 Tag 并不能自动改变炸弹行为。不可引爆炸弹的机关必须挂载对应机关组件，由组件明确返回“继续飞行”。

## 1. 核心系统

### 1.1 角色的行为与状态机

#### 1.1.1 角色移动

当前主要组件：`pl_Move`

当前已经支持：

- 相机朝向相关的平面全向移动。
- 平滑加速、减速和转向。
- 基础坡面贴合与台阶跨越。
- 墙面阻挡和沿墙滑动。
- 重力下落。
- 站在移动铁块上时跟随铁块位移。
- 识别 `Ground`、跳板和隐形道路为可站立表面。

当前尚未形成独立完整参数的功能：快速移动/冲刺、快速移动加速度、最大坡度、上坡速度倍率、独立重力倍率、最大下落速度。添加这些功能前不要在文档或关卡中假设它们已经生效。

场景配置：

1. 玩家根物体添加 `Capsule Collider` 和 `pl_Move`。
2. 为 `pl_Move` 绑定 `Input Manager`、`State Manager`、`Camera Transform` 和玩家胶囊体。
3. 普通可站立地块设置 Tag 为 `Ground`。
4. 墙体所在 Layer 加入 `Wall Mask`。
5. 可推动铁块所在 Layer 加入 `Movable Mask`。
6. 跳板和隐形道路不需要改成 `Ground`，3C 会通过组件识别。

常用字段：

- `Max Move Speed`：基础最大移动速度。
- `Acceleration Time`：加速到最大速度所需时间。
- `Deceleration Time`：松开输入后的减速时间。
- `Max Turn Speed`：每秒最大转向角度。
- `Player Height`：地面吸附计算所用角色高度，应与胶囊尺寸匹配。
- `Ground Snap Distance`：可向下吸附到地面的距离。
- `Skin`：碰撞安全间距。
- `Step Offset`：最大台阶检测高度。

测试：

1. 在平地进行八方向移动和转向。
2. 走上坡面，检查是否贴地且没有明显跳动。
3. 走过小台阶并撞向高墙。
4. 站到铁块、跳板和隐形道路上，检查是否能稳定站立。

#### 1.1.2 角色的投弹

主要组件和资源：

- `BombThrower`
- `BombProjectile`
- `GravityController`
- `BombBlastWave`
- `Assets/Prefab/Objects2/Bomb.prefab`

工作流程：

1. `BombThrower` 从 `Throw Origin` 生成炸弹。
2. 炸弹根据 `Horizontal` 或 `Angled` 轨迹取得初速度。
3. 普通碰撞会触发爆炸；特殊机关可以捕获、运输、弹射或击落炸弹。
4. 直接接触破坏只通过 `IBombDirectHitReceiver` 路由给命中对象。
5. 爆炸创建扩张的 `BombBlastWave`，按 `Blast Speed` 从中心向外检测对象。
6. 上一颗炸弹完成爆炸、解除或销毁后，投弹锁才会释放。

玩家配置：

1. 玩家添加 `BombThrower`。
2. `Bomb Prefab` 指向 `Prefab/Objects2/Bomb.prefab`。
3. 在玩家模型中心上方创建空物体作为 `Throw Origin`。
4. 如果启用 `Use Camera Direction`，绑定主摄像机 Transform。
5. 投弹输入来自 `InputSystem_Actions/Player`：鼠标右键瞄准，鼠标左键确认。

轨迹字段：

- `Throw Speed`：炸弹初始速度。
- `Trajectory = Horizontal`：平抛，不提供初始向上速度。
- `Trajectory = Angled`：斜抛。
- `Angled Throw Degrees`：斜抛仰角。
- `Fallback Throw Height`：未绑定 `Throw Origin` 时使用的备用生成高度，不是轨迹最高点。
- `Maximum Throw Lock Duration`：丢弹锁的安全超时，不是炸弹寿命。

炸弹 Prefab：

- `Blast Radius`：最大冲击波半径。
- `Blast Speed`：冲击波扩张速度。
- `Blast Layers`：冲击波可以检测的 Layer。
- `Maximum Lifetime`：安全引信时间。
- `GravityController/Gravity Multiplier`：炸弹实际重力倍率。

测试：

1. 投出一颗炸弹，确认生成位置和方向正确。
2. 炸弹撞击普通地面后爆炸。
3. 冲击波圆环应从爆炸点扩张。
4. 第一颗炸弹未完成前不能生成第二颗。
5. 第一颗销毁后应恢复投弹；若未恢复，查看 `BombThrower` 的诊断信息。

投弹提示线操作：

1. 直接点击鼠标左键可以不瞄准、立即投出炸弹。
2. 按住鼠标右键后立即显示预测虚线。
3. 保持右键按住并点击鼠标左键，会按照当前预览轨迹投出炸弹。
4. 松开右键只会取消瞄准，不会自动投弹。
5. 白色虚线表示预测爆炸不会覆盖玩家；红色虚线表示预测爆炸点的冲击波会覆盖玩家。
6. 上一颗炸弹尚未完成时继续按住右键，轨迹会从黄色逐渐变为白色，表示下一颗炸弹的准备进度。
7. 实际投弹锁解除时，安全轨迹完全变白；危险轨迹恢复为红色。
8. `BombTrajectoryPreview` 可以调整线宽、虚线长度、预测时间、采样间隔和碰撞 Layer。

##### 投弹 BUFF：传送炸弹

主要组件：

- 玩家：`BombBuffController`
- 传送目标：`BombTeleportTarget`
- 运行时测试窗口：`Tools > Super Final Fuse > Bomb Buff Runtime`

配置传送器：

1. 在传送器碰撞物体上添加 `BombTeleportTarget`。
2. 创建 `Destination` 空物体，放在玩家传送后的安全位置。
3. 绑定 `Destination`。
4. 根据需要启用 `Copy Destination Rotation`。
5. 设置 `Post Teleport Immunity Duration`，玩家传送触发后会短暂无视炸弹冲击波。

运行时测试：

1. Play 后打开 `Tools > Super Final Fuse > Bomb Buff Runtime`。
2. 点击 `Find Player`。
3. 添加传送炸弹 Buff，并设置层数为 1、持续时间为无限。
4. 投弹命中传送器。
5. 玩家应传送到目标位置，Buff 减少一层，并获得短暂无敌。

#### 1.1.3 角色的其他行为

传送由 `BombTeleportTarget` 和 `BombBuffController` 协作完成。

跳板强制移动由 `BombJumpPad` 和运行时自动添加的 `JumpPadPlayerFlight` 完成。跳板飞行期间暂时停用 `pl_Move`，落地后恢复，不会强制修改玩家朝向。

### 1.2 摄像机系统

#### 1.2.1 一般的后跟随摄像机

当前项目摄像机部分不在本轮机关系统的完整实现范围内。现有关卡可继续使用当前跟随摄像机，但以下内容应视为规划项：

- 地下、地面、平台三种高度角状态。
- 左斜、正后、右斜三种地图控制视角。
- 区域强制缩放限制。
- 分层遮挡处理。
- 完整的距离、加速度、回正和 FOV 参数组。

在摄像机系统正式重构前，不建议机关脚本直接控制主摄像机。机关应通过事件或地图区域组件向未来摄像机控制器发出状态请求。

### 1.3 游戏对象/炸弹交互系统

#### 1.3.1 一般环境

普通环境需要：

- 非 Trigger Collider。
- 被 `Bomb.prefab` 的 `Blast Layers` 包含。
- 如果玩家需要站立，使用 `Ground` Tag。

炸弹默认在第一次普通碰撞时爆炸。特殊机关不应只依赖 `air` Tag，而应挂载管道、跳板、轨道平台、防空区等对应组件。

#### 1.3.2 碎石块

推荐 Prefab：`Prefab/Objects2/BombContactBreakable.prefab`

主要组件：`BombContactBreakable`

配置：

1. 在碎石根物体添加 `BombContactBreakable`。
2. `Renderers To Hide` 填入破坏后需要隐藏的 Renderer。
3. `Colliders To Disable` 填入破坏后需要关闭的 Collider。
4. `Break Effect Prefab` 可选择粒子效果；留空则只执行实体隐藏/碎块方案。
5. 设置 `Effect Lifetime`。

碎石实现了存档参与接口。存档时记录完整/破坏状态，玩家死亡后恢复到最近存档时状态，而不是简单依据当前 Collider 状态推断。

测试：炸弹必须直接命中碎石；仅冲击波经过不应触发直接破坏。

#### 1.3.3 传送器

推荐 Prefab：`Prefab/Objects2/BombTeleportEntrance.prefab`

主要组件：`BombTeleportTarget`

没有传送 Buff 时，它按照普通炸弹接触逻辑处理；拥有 Buff 时，命中会调用玩家传送流程、消耗一层 Buff，并给予传送后的短暂无敌。

#### 1.3.4 跳板

推荐 Prefab：`Prefab/Objects2/JumpPad.prefab`

主要组件：`BombJumpPad`

配置：

1. 跳板使用实体 Collider，`Is Trigger` 关闭。
2. 添加 `BombJumpPad`。
3. `Direction` 选择 Forward、Backward、Left 或 Right；方向基于跳板自身 Transform。
4. 设置炸弹和玩家各自的弹射距离与高度。
5. `Launch Delay` 控制站稳后到弹射的等待时间。
6. `Top Detection Height` 和 `Player Detection Height` 是顶面检测容差，不宜过大。

预览：

- 绿色轨迹为炸弹。
- 青色轨迹为玩家。
- 绿色轨迹会直接读取 `Prefab/Objects2/Bomb.prefab` 上的 `GravityController` 倍率。

测试：

1. 玩家从顶面落到跳板，等待后弹射；侧面不能触发。
2. 炸弹从顶面落下，不爆炸，清除旧速度后弹射。
3. 在第一条轨迹落点放置第二个跳板，测试连续弹射。

#### 1.3.5 管道

推荐 Prefab：`Prefab/Objects2/BombPipe.prefab`

主要组件：`BombPipe`

标准层级：

```text
BombPipe
├─ Entrance
├─ CapturePoint
├─ Exit
└─ Visual
   └─ Model
```

配置：

1. `Entrance`、`Exit` 为两端检测点，管道支持双向进入。
2. `Capture Point` 位于内部暂存位置。
3. `Internal Travel Speed` 决定内部运输速度。
4. 实际等待时间由管道长度除以内部运输速度计算，因此与长度成正比。
5. `Exit Speed` 是释放速度。
6. `Released Bomb Ignore Duration/Distance` 防止出口检测器立刻重新捕获炸弹。
7. `Accepted Owners` 可以多选允许进入的炸弹来源。

调整尺寸：打开 `Tools > Bomb Throwing > Bomb Pipe Size Editor`。编辑器只缩放 `Visual/Model` 的 X 长度，入口和出口 Collider 保持大小不变并移动到两端表面。

#### 1.3.6 轨道平台

推荐 Prefab：

- `Prefab/Objects2/BombRailPlatform.prefab`
- `Prefab/Objects2/RailPath(Example).prefab`

主要组件：`BombRailPlatform`

配置：

1. 创建多个空物体作为 `Waypoints`。
2. 按行进顺序填入数组。
3. 选择路线模式。
4. 设置 `Move Speed` 和 `Wait At Waypoint`。
5. `Play On Awake` 控制是否自动开始。
6. `Transported Bomb Owners` 选择可运输的炸弹来源。

平台不会引爆被运输的炸弹，并通过水平运动驱动携带玩家或炸弹。可使用 `Play/Stop/Toggle` 接入机关事件。

#### 1.3.7 隐形道路

推荐 Prefab：`Prefab/Objects2/RevealablePlatform.prefab`

主要组件和资源：

- `RevealablePlatform`
- `PlatformRevealManager`
- `Shader/Custom_TransparantPlatform.mat`

配置：

1. 保留实体 Collider，关闭 `Is Trigger`。
2. 添加 `RevealablePlatform`。
3. Renderer 使用 `Custom_TransparantPlatform.mat`。
4. Tag 和 Layer 可以保持默认；3C 会通过组件把它识别为道路。
5. 设置 `Reveal Radius`、`Visible Duration`、`Fade Duration`。

效果：玩家炸弹爆炸后，以爆炸点为中心显示指定范围的道路，保持一段时间后逐渐透明。Collider 在整个过程中始终有效。

右键组件执行 `Test Reveal At Road Centre` 可以不投弹测试。TA可以调用 `RevealAt`，或监听显形、开始淡出、恢复透明事件。

#### 1.3.8 炸药桶

推荐 Prefab：`Prefab/Objects2/ExplosiveBarrel.prefab`

主要组件：`ExplosiveBarrel`

触发方式：

- 被允许来源的炸弹直接命中。
- 从超过 `Minimum Fall Height` 的高度落地。
- 位于其他炸药桶的连锁范围内。

字段：

- `Direct Hit Owners`：允许触发直接爆炸的炸弹来源。
- `Shockwave Push Impulse`：普通炸弹冲击波仅经过时的推动力度。
- `Minimum Fall Height`：高坠爆炸阈值。
- `Blast Radius/Speed/Layers`：炸药桶自身爆炸波。
- `Chain Reaction Radius/Layers`：连锁爆炸范围。

炸药桶实现存档状态恢复。配置 `Renderers To Hide` 和 `Colliders To Disable`，不要在爆炸时直接销毁整个根对象。

#### 1.3.9 铁块

推荐 Prefab：`Prefab/Objects2/IronBlock.prefab`

主要组件：`BombMovableIron`

配置：

1. 根物体需要 Rigidbody 和实体 Collider。
2. 保持重力开启。
3. 根据 Prefab 设置冻结旋转，避免推移过程中倾倒。
4. `Move Distance` 设置每次炸弹命中的格数距离。
5. `Move Duration` 设置机关移动时间。
6. `Blocking Layers` 包含墙和铁块所在 Layer。
7. `Minimum Iron Center Distance` 通常与一个格子的中心距离一致。

行为：炸弹直接命中四个水平面之一后，铁块沿相反方向移动。前方墙或另一铁块会阻挡移动；铁块之间不依靠普通 Rigidbody 推力互相推动。

#### 1.3.10 防空炮

推荐 Prefab：`Prefab/Objects2/BombAntiAirZone.prefab`

主要组件：`BombAntiAirZone`

配置：

1. 使用 Box Collider 或 Sphere Collider 表示区域。
2. Collider 会自动设置为 Trigger。
3. 区域 Y 尺寸需要覆盖炸弹飞行高度。
4. `Intercepted Owners` 是多选字段，默认只勾选 `Player`。
5. `Drop Speed` 设置击落后的初始向下速度。
6. 可将 `Map Indicator` 绑定到地图图标或范围对象。

行为：指定来源的炸弹进入区域后清除原速度，垂直坠落，撞地后正常爆炸。它不会直接消失。玩家进入时显示边界并启用 Map Indicator，离开时隐藏。

如果只希望小地图显示范围，可把区域放到专用 Layer，让主摄像机排除、小地图摄像机包含该 Layer。

#### 1.3.11 物理属性平台

推荐 Prefab：`Prefab/Objects2/PhysicsPropertyPlatform.prefab`

主要组件：`PhysicsPropertyPlatform`

配置：

1. 添加 Rigidbody 和实体 Collider。
2. `Use Gravity` 开启，`Is Kinematic` 关闭。
3. `Freeze Rotation` 通常开启。
4. `Restore To Game Start` 开启时，复活会恢复到游戏开始位置，而不是保存时已经下落的位置。

典型关卡流程：用碎石支撑平台；炸毁碎石后平台下落；玩家死亡后碎石和平台一起恢复。恢复后系统会重新唤醒 Rigidbody 并保留重力。

#### 1.3.12 炸弹生成器

推荐 Prefab：`Prefab/Objects2/BombGenerator.prefab`

主要组件：`BombGenerator`

配置：

1. `Bomb Prefab` 使用与玩家相同的 `Bomb.prefab`。
2. 创建 `Spawn Point`，其 Forward 表示发射方向。
3. `Spawn Interval` 设置生成间隔。
4. `Launch Speed` 设置射出速度。
5. `Start Generating` 控制开局是否工作。
6. `Spawn Immediately` 控制开局是否立即生成第一颗。
7. `Maximum Active Bombs = 0` 表示不限制；大于零时限制同时存在数量。
8. `Generator Colliders To Ignore` 填入发射器自身 Collider，避免刚生成就撞到机器。

可通过 `StartGenerating/StopGenerating/ToggleGenerating/GenerateBomb` 接入开关。生成器炸弹和玩家炸弹使用相同 `BombProjectile`，因此能炸碎石、推动铁块并进入管道。

### 1.4 玩家的生命与复活

#### 1.4.1 复活机制

玩家所需组件：

- `PlayerHealth`
- `BombPlayerRespawn`
- `PlayerCheckpointManager`
- `VoidFallRespawn`

存档点推荐 Prefab：`Prefab/Objects2/Checkpoint.prefab`

配置玩家：

1. 添加 `BombPlayerRespawn`，它会要求 `PlayerHealth` 和 `PlayerCheckpointManager`。
2. 设置 `Respawn Delay`。
3. `Controls To Disable` 可加入移动和交互脚本；`BombThrower` 可以加入，系统会阻止输入但保持组件启用，以继续处理炸弹锁。
4. 不要把 `BombPlayerRespawn` 自己加入该数组。
5. `Visual Root` 指向需要播放倒地旋转的模型根节点。

配置存档点：

1. 添加 `PlayerCheckpoint`，Collider 设置为 Trigger。
2. 创建 `Respawn Point`，避免与墙或地面重叠。
3. `Activate Only Once` 表示该点只触发一次；关闭后重复经过仍会更新为这个点。
4. 多个存档点分别绑定自己的 Respawn Point，不要都指向初始点。

存档时会捕获实现 `ICheckpointStateParticipant` 的对象状态，包括碎石、铁块、管道、轨道平台、物理平台、炸药桶、生成器等。死亡恢复顺序由 `PlayerCheckpointManager` 统一管理。

当前 Buff 行为是“恢复到最近一次存档时的 Buff 快照”，并非每次死亡后无条件清空。如果最终策划规则确定为死亡清空全部 Buff，需要再调整 `PlayerCheckpointManager` 的 Buff 恢复策略。敌人、收集物和 BGM 也必须各自实现存档参与接口或连接存档事件后，才能被统一恢复；仅放进场景不会自动获得存档能力。

虚空复活：

- `VoidFallRespawn` 只检测玩家是否低于 `Void Height`。
- 它不再保存独立复活点，而是调用生命和存档系统。
- 调整 `Void Height` 到关卡最低有效区域下方。

#### 1.4.2 玩家 HP

主要组件：`PlayerHealth`

默认数值：

- `Maximum Health = 2`
- `Normal Bomb Blast Damage = 1`
- `Own Bomb Blast Damage = 2`

伤害来源：

- 普通炸弹冲击波：通常 1 点。
- 自己投出的炸弹冲击波：2 点，满血也会直接死亡。
- 岩浆：使用 `PlayerDamageVolume`，推荐伤害设置为 2、类型选择 `Lava`。
- 虚空：`VoidFallRespawn` 调用 `Kill`。

岩浆推荐 Prefab：`Prefab/Objects2/Lava.prefab`

岩浆配置：

1. 添加 Trigger Collider 和 `PlayerDamageVolume`。
2. `Damage = 2`。
3. `Damage Type = Lava`。
4. `Damage Once Per Entry` 开启即可直接进入死亡流程。

玩家 HP 降到 0 后触发统一复活流程。复活结束会恢复最大 HP、玩家控制、动画姿态和最近存档机关状态。

## 2. 通用排错清单

### 炸弹没有触发机关

1. 确认使用的是 `Prefab/Objects2/Bomb.prefab` 或带 `BombProjectile` 的同类 Prefab。
2. 确认机关 Collider 已启用。
3. Trigger 机关需要炸弹 Rigidbody 正常参与物理检测。
4. 检查 `BombOwnerMask` 是否勾选了炸弹来源。
5. 检查炸弹 `Blast Layers` 是否包含目标 Layer。

### 玩家穿过看起来有 Collider 的对象

`pl_Move` 的竖直落地不是单纯依赖 Rigidbody 碰撞。普通地面应使用 `Ground` Tag；跳板和隐形道路由对应组件自动识别。

### 炸弹碰到 air 仍然爆炸

`air` Tag 只是分类信息。对象还必须挂载能处理 `IBombDirectHitReceiver` 的机关组件，例如 `BombJumpPad`、`BombPipe` 或 `BombRailPlatform`。

### 玩家死亡后机关没有恢复

1. 确认机关实现了 `ICheckpointStateParticipant` 或挂载 `CheckpointResettable`。
2. 确认存档点实际触发过。
3. 不要在机关变化时直接销毁需要恢复的根对象；优先隐藏 Renderer、禁用 Collider并保存状态。
4. 动态 Rigidbody 恢复后需要保持正确的 `Use Gravity/Is Kinematic` 状态。

### 投弹永久锁住

检查 `BombThrower` 的：

- `Active Bomb Instance ID`
- `Current Lock Age`
- `Last Diagnostic Event`
- `Maximum Throw Lock Duration`

不要通过禁用整个 `BombThrower` 来阻止重生期间投弹，应调用其输入阻止逻辑。

## 3. 建议的关卡制作流程

1. 从 `Prefab/Objects2` 拖入机关 Prefab。
2. 先只搭建 Collider、方向点、路径点和出生点。
3. 在 `BombTest_REElevel 04` 单独验证机关。
4. 再配置材质、粒子、音效和 UnityEvent。
5. 设置一个存档点，改变机关后主动死亡，验证状态恢复。
6. 同时用玩家炸弹和生成器炸弹验证 Owner Mask。
7. 最后再制作正式关卡 Prefab Override，避免把测试引用保存进通用 Prefab。
